🔧 project info — brand support ai agent

hiver sde intern take-home assignment

📌 what this project is

an ai-powered customer support agent for a single brand, built using real twitter support conversations. the system classifies customer intents, drafts replies grounded in historical brand behavior, and decides whether to auto-respond or escalate to a human.

the emphasis is on proving the system works — evaluation, baselines, failure analysis, and reproducibility matter more than a fancy model.

📊 datasets

primary: customer support on twitter

primary ~3M tweets
  • source: kaggle — thoughtvector/customer-support-on-twitter
  • format: csv
  • size: ~3 million tweets
  • content: real customer-brand conversations on twitter across dozens of brands
  • key columns:
columndescription
tweet_idunique tweet identifier
author_idtwitter user who wrote the tweet
inboundtrue if customer message, false if brand reply
created_attimestamp of the tweet
textthe tweet content
response_tweet_idid of the tweet this is replying to (for threading)
in_response_to_tweet_idid of the original tweet being responded to
note: data is real and noisy — expect missing fields, broken thread chains, duplicate tweets, and non-english content. cleaning is a significant part of the work.

optional secondary: banking77

optional intent only
  • source: hugging face — PolyAI/banking77
  • format: hugging face dataset
  • size: ~13,000 queries
  • content: 77 labelled banking intents
  • use case: can be used to supplement intent classification work, test intent models, or as a reference for intent taxonomy design

🛠️ tools & technologies

language & runtime

python 3.10+
  • python is the primary language
  • notebooks for exploration only — production code in .py files

data processing

pandas numpy
  • pandas: data loading, filtering, cleaning, csv i/o
  • numpy: numerical operations, array handling

machine learning / nlp

scikit-learn sentence-transformers
  • scikit-learn: tfidf vectorizer, logistic regression (simple baseline), metrics (f1, confusion matrix)
  • sentence-transformers: text embeddings for semantic similarity (reply retrieval)

llm integration

openai / any llm api
  • any llm api or open model is allowed
  • used for: intent classification (few-shot), reply generation, llm-as-judge evaluation
  • candidates: openai gpt-4o-mini, google gemini, anthropic claude, local models via ollama
decision needed: which llm to use will be decided during implementation based on cost, availability, and quality.

evaluation

bleu rouge f1 cohen's kappa
  • intent: accuracy, macro-f1, confusion matrix
  • reply quality: bleu, rouge (automated); llm-as-judge (tone, accuracy, helpfulness)
  • escalation: precision, recall, f1 on escalation decisions
  • judge agreement: cohen's kappa between llm-judge and human scores

dev tools

git github pip
  • git/github: version control and submission
  • pip: dependency management via requirements.txt
  • ai coding assistants: allowed (must be able to explain and modify code live)
